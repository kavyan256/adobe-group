AI-Readiness Audit v5 Plan

Scripts keep measuring. The agent becomes the judge of what they measured, and a script checks every judgement against the crawl before it changes the report.

What the brief asks for

“encode that reasoning into reusable agent skills, so that a general AI agent, pointed at any website, can audit it automatically”Problem statement, introduction
“We evaluate the submitted marketplace itself — its skills' instructions, checks, logic, and how they're composed by the entrypoint”Section 3, how submissions are evaluated

The brief wants both halves. The SKILL.md template asks for numbered, deterministic steps and says to push executable checks into scripts/, so scripts are the intended tool. But the thing being graded is the reasoning the skill teaches a general agent. In v4 the agent launches scripts and may optionally add a few low findings. It never applies judgement to the findings that matter.

Where v4 falls short

Every point below comes from the 100-site evaluation and from checking each severe finding against the raw pages.

  • The agent was never tested. All 415 findings in the 100-site run came from scripts. The harness called the Python entrypoint directly, so it measured the scripts, not the skill.
  • The agent cannot correct a script. It may add up to six claims capped at low. Of the 33 severe findings outside the robots-posture question, 11 were false or overstated, and nothing in v4 could catch them.
  • Scripts cannot see context. A robots.txt timeout read as a site-wide block (kraken, muji). A maintenance or geo-block page read as a wall against bots (fnac, magalu). An empty 404 page and a test page read as broken shells (supercell, websummit). Noindex on duplicate or staff pages read as critical (mcmaster, msf).
  • The crawler creates some defects itself. It strips trailing slashes, which produced 6 of the 12 broken-page URLs in the run (all on tfl). The new commerce-evidence rule also lost bluebottle's price-only-in-page-data finding.
  • Reasoning-heavy mechanisms are thin. Identity confusion, promise versus payoff and visitor orientation are judged by regex or not at all.

The v5 design: a verdict layer

The scripted report stays exactly as it is today, deterministic and reproducible. On top of it, the agent issues a verdict on every finding at medium or above, and a verifier decides whether that verdict may change anything.

  1. ScriptCrawl once and run the scripted checksUnchanged: robots.txt respected, 12 pages, four scripted skills, one report.
  2. ScriptProfile the crawlA compact view of every page, plus each scripted finding's severity and evidence.
  3. AgentJudge every medium-or-above findingWalk the questions in references/adjudication.md and write a verdict: confirm, downgrade, confirm intent or not a defect, with a reason code and checkable evidence.
  4. AgentAdd claims and site-specific fixesAs in v4: problems no script covers, and fixes that quote the page.
  5. ScriptVerify, then applyEvery assertion must hold against the crawl, the reason must fit the kind of finding, and the effect is fixed by the reason code, never by the agent.
  6. ReportRecord before and afterEach change keeps the original severity and status. Removed findings move to agent_review.adjudicated_out with their evidence, so nothing disappears silently.

The agent can never raise a severity, invent a reason, or use knowledge from outside the crawl. A verdict that fails any rule changes nothing and is listed with the reason it was rejected.

Tested before building

The verdict layer was prototyped in a copy of the marketplace, so the real solution is untouched. Pass criteria were written down before any scored run.

  • Agent: headless Claude Code on Sonnet, a mid-tier general agent, so a pass is conservative. It had file tools, python3 and read-only shell commands, with no web access.
  • Development set: the 39 severe findings from the 100-site run, graded against raw pages before the prototype existed.
  • Held-out set: 18 medium findings on 17 other sites, graded blind before any agent ran. The judging reference contains none of their specifics.
  • Verifier controls: 13 hand-written verdicts, 9 with fabricated or wrongly scoped evidence that must be rejected and 4 genuine ones that must be accepted.
Status: the verifier controls and a three-run pilot passed. The scored test has not run. After the pilot the account reached its monthly spend limit, so all 63 scored agent runs stopped before writing a report. Nothing below is a scored result.

Fixed during the pilot, before scoring

  • Harness permissions. The first pilot blocked the skill's own profile command, which pushed one run to 400 s. The scored harness allows file edits, python3 and read-only shell tools, and still denies web access.
  • A reason used out of scope. The agent called disabled zoom “deliberate configuration”. That reason now applies only to indexing and access findings, enforced by the verifier and backed by a control.

Build plan

Phases run in order because each one's acceptance check depends on the previous phase.

Phase A · Crawler and check fixes can start now

These fixes are deterministic and don't depend on the verdict layer. Each one removes a false finding found in the evaluation.

  • Keep trailing slashes. The URL normalizer strips them, which produced 6 of the 12 broken-page URLs in the run.
  • Separate network failures from site blocks. On a robots.txt timeout or connection error, retry once, then report “could not audit from this network” instead of a critical unreadable-site finding.
  • Read the refused page before calling it a bot wall. A 403 whose body is a maintenance or unavailable-here page becomes a question for the owner.
  • Skip error pages in the empty-shell check. A page titled “not found” is excluded.
  • Accept a price in page data as commerce evidence. This restores the lost bluebottle finding.

Done when: all tests pass, all 100 saved crawls are replayed, and every changed finding is spot-checked with no new severe false positive.

Phase B · Verdict layer in the entrypoint after the scored test

  • Apply verdicts inside the entrypoint before ranking, so severity, priorities and finding IDs are recomputed by the existing model.
  • Add adjudications, rejected verdicts, removed findings and unjudged findings to the report schema.
  • Ship the judging reference, the verdict verifier, and the profile with each finding's severity and evidence.
  • Turn the 13 controls into unit tests.

Done when: tests and the validator pass, and replaying the pilot's verdicts reproduces the same report.

Phase C · Judgement becomes a required step after B

  • The entrypoint's procedure requires the judging step. A report without it says so in its headline.
  • The README and manifest describe the split: scripts measure, the agent judges, a script verifies.

Done when: a headless agent given only the entrypoint SKILL.md produces a judged report on 3 sites.

Phase D · Test the skill the way graders run it after C

  • Run a headless agent end to end, crawl plus judgement, on 20 live sites never used before.
  • Grade those findings blind before the runs, with the same pre-registered criteria.

Done when: the criteria pass and every audit finishes within 5 minutes.

Phase E · Docs, zip and commit last

Done when: the zip is rebuilt, unzipped and tested, and the validator says SUBMITTABLE.

Risks and open decisions

  • Runtime and cost. The agent step took 2 to 3.5 minutes on top of a 30 to 140 second crawl, at about $0.55 to $0.66 a site. A slow crawl plus a slow agent can pass 5 minutes. The mitigations are a 12-page crawl, verdicts only on medium or above, and skipping claims when time is short.
  • The graders' agent is unknown. A weaker agent writes fewer or worse verdicts. The verifier limits the damage, because a verdict that doesn't hold changes nothing and the scripted report stays the floor.
  • Determinism. The scripted layer stays identical on replay. The agent layer varies between runs, so every change is recorded with its evidence and stability is measured.
  • Overfitting. The reason codes grew out of errors found in this evaluation. The held-out set and Phase D's new sites exist to catch that.
  • Arguable verdicts. The pilot merged supercell's title finding into the empty-shell finding on the same gift pages. The rules allow it, but a reviewer could disagree.

Decisions for you

  • Spend limit. Raise it to finish the scored test, or accept the pilot evidence and start Phase A only.
  • Named AI-agent blocks in robots.txt. News sites such as bbc, npr and spiegel block OpenAI and Perplexity agents by name. Decide whether that is a critical defect or a confirm-intent question. The verdict layer deliberately leaves it to the scripted check until you decide.
