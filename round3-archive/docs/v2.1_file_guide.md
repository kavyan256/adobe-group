# brand-ai-readiness-audit-v2.1 — file-by-file guide

What every file in the marketplace does, and what its contents do. Written against the
compressed v2.1 (after the 2026-09-11 clean-up). Line counts are approximate.

This guide lives in `docs/`, outside the marketplace root, so it is not part of the
submission zip.

---

## How the pieces fit together

```
audit.py <url>                                   (audit-orchestrator/scripts)
  │
  ├─ bundle.py  ── fetches the site once ─────────► site bundle (JSON)
  │    └─ robots.py  (parses robots.txt, classifies AI crawlers)
  │
  ├─ runs 4 sub-skill scripts as separate processes, each reading the bundle:
  │    crawl-access-audit/scripts/check_access.py
  │    fact-extractability-audit/scripts/check_extractability.py
  │    freshness-corroboration-audit/scripts/check_freshness.py
  │    engagement-audit/scripts/check_engagement.py
  │
  ├─ model.py  ── turns raw findings into scored findings (severity, hurts tag)
  │
  └─ writes one report.json  (shape defined by schema/audit-report.schema.json)
```

Each skill folder follows the agentskills.io layout:
`SKILL.md` (instructions an agent reads) · `scripts/` (code that runs) ·
`references/` (detailed rules the SKILL.md points to).

## Marketplace root

### `marketplace.json` (34 lines)
The manifest the problem statement requires. Lists the five skills with an `id`, a
`path` to the folder, and a one-line `summary`. Marks `audit-orchestrator` as the only
`"entrypoint": true`. Also carries the marketplace `name`, `version` (2.1.0),
`description` and `license` (Apache-2.0).

### `README.md` (114 lines)
The root README the submission needs. Sections:
- **Intro + quick start** — what the tool does, that it is read-only, the two commands to run it.
- **The skills** — table of the five skills, the concern each owns, and which check IDs belong to it.
- **How the entrypoint composes them** — ASCII diagram of crawl → 4 skills → merge, and why the skills share data, not code.
- **The report** — the required fields plus the extras (`hurts`, `how`/`verify`, `prioritized_actions`, `proactive_recommendations`, `status`, `checks_skipped`, `limits`).
- **Design decisions** — no headless browser, training vs retrieval crawlers, deliberate vs defective, severity as a table; each points to its reference doc.
- **What a site crawl cannot see** — personalization, email summarisation, cross-web corroboration (D6), contrast/Core Web Vitals.
- **Guarantees** — truthful user-agent, robots.txt respected, 280 s bound, determinism, dependencies.
- **Tests** — how to run the test suite.

### `requirements.txt` (4 lines)
The two third-party dependencies with version ranges: `httpx` (HTTP client) and
`beautifulsoup4` (HTML parsing). Install with `pip install -r requirements.txt`.

### `schema/audit-report.schema.json` (301 lines)
JSON Schema (draft 2020-12) for the report the entrypoint emits.
- **Top-level `required`**: `site`, `audited_at`, `summary`, `findings` — the floor from the problem statement.
- **`summary`**: requires `total_findings`, `critical`, `high`, `medium`; also defines `low`, `info`, `active_findings`, `latent_findings`, `confirm_intent_findings`, `by_hurts`, `run_status`, `headline`.
- **`findings[]`**: requires `id` (pattern `F-001`), `title`, `severity`, `evidence`, `suggested_action` (`summary` + `priority`, optional `effort`/`how`/`verify`); defines the extra fields `check_id`, `hurts`, `gate`, `mechanism`, `status`, `confidence`, `measurement_basis`, `blast_radius`, `severity_rationale`, `affected_urls`, `affected_url_count`, `blocked_by`, `detail`, `intent_signals`.
- **Other sections**: `site_profile`, `coverage`, `checks_skipped[]` (`check` + `reason` + `impact`), `prioritized_actions`, `proactive_recommendations`, `already_in_place`, `limits`, `notes`.

## `skills/audit-orchestrator/` — the entrypoint

### `SKILL.md` (71 lines)
Frontmatter (`name`, `description`, `license`, `allowed-tools: Bash, Read, Write`) and
the four required sections:
- **When to use** — "why doesn't ChatGPT mention my site", "why don't AI visitors stay", general AI-readiness audits; never to change a site.
- **Inputs** — table of `url`, `--max-pages`, `--bundle`, `--replay`, `-o`.
- **Procedure** — 6 steps: fetch once → run the four skills → mark latent → derive severity + `hurts` → prioritize + proactive recommendations → emit the report.
- **Output** — the report's required and extra fields.
- **References** — pointers to the three reference docs.

### `scripts/audit.py` (380 lines) — the orchestrator
The command you run. Contents, top to bottom:
- **Imports / setup** — turns off `__pycache__` writing so the zip stays clean; imports `Finding` from `model.py` and `bundle.py`.
- **`SUB_SKILLS`** — the four `(folder, script)` pairs to run.
- **`SEV_WEIGHT`, `EFFORT_WEIGHT`** — numbers used by the priority score.
- **Proactive helpers** (`_ok_derived`, `_has_llms_txt`, `_names_ai_agents`, `_has_faq_markup`, `_has_sameas`, `_is_hydrated_app`) — small yes/no tests on the bundle.
- **`PROACTIVE`** — five "beyond the defects" recommendations (publish `llms.txt`; decide an AI-crawler policy; add FAQ markup; publish a citable facts page; server-render key facts in a SPA). Each has an `applies` test so it is only recommended when the site doesn't already do it.
- **`proactive_for()`** — splits `PROACTIVE` into `proactive_recommendations` (applies) and `already_in_place` (site already does it).
- **`run_sub_skill()`** — runs one skill script as a subprocess with a timeout; if the script is missing, times out, crashes or prints bad JSON, it returns a `checks_skipped` entry instead of failing the audit.
- **`mark_latent()`** — if A1 (retrieval agents blocked) or A3 (noindex) fired, marks downstream findings on those blocked URLs/paths as `status: "latent"` with a `blocked_by` naming the affected agents.
- **`priority_score()`** — `severity × confidence × status_weight ÷ effort`; latent ×0.35, confirm-intent ×0.5.
- **`build_report()`** — assembles the final report: required fields, summary counts (active findings only), `by_hurts`, `run_status`, `headline`, sorted findings, `site_profile`, `coverage`, `checks_skipped`, top-15 `prioritized_actions`, proactive recommendations, `limits`, `notes`.
- **`_ai_policy()`** — lists which retrieval vs training agents robots.txt fully blocks, with a note that training blocks don't affect citation.
- **`_headline()`** — one-sentence summary: the site is unreadable, nothing blocking was found, or "N finding(s); most severe: …".
- **`main()`** — parses CLI args; builds a bundle (or loads one with `--replay`); writes it to a temp file outside the marketplace; runs the four skills inside the shared 280 s budget; deletes the temp file; marks latent; sorts; wraps each raw finding in `Finding(...).finalise()`; prints or writes the report.

### `scripts/bundle.py` (592 lines) — the single crawl
Fetches the site once and writes the "site bundle" every skill reads.
- **Constants** — `USER_AGENT` (`AIReadinessAudit/1.0`), `DEFAULT_MAX_PAGES` 20, `DEFAULT_DEADLINE_S` 200 (crawl), `TOTAL_BUDGET_S` 280 (whole audit), `MAX_HONOURED_CRAWL_DELAY` 2 s, per-request timeout 12 s, 3 MB page cap, `BUNDLE_SCHEMA_VERSION` 2.
- **`_httpx()`** — imports `httpx` lazily, so `--replay` and tests work without it.
- **`ROLE_PATTERNS` + `infer_role()`** — classifies each URL as `home`, `pricing`, `contact`, `product`, `about`, `blog`, `legal`, `search`, `utility` or `generic` from its path. Skills use the role to decide what a page should contain.
- **JSON-LD normalisation** (`_types_of`, `_walk_nodes`, `_record`, `_flatten_scalars`, `normalise_jsonld`) — reads every `ld+json` block, flattens `@graph`, lowercases and strips `@type` prefixes, keeps nested entities in place, counts malformed vs empty blocks, and gathers `types_present`, `sameas`, `dates` and a flat `text`.
- **`normalise_text()`** — produces the two page texts every skill uses: `extracted` (navigation, header, footer, aside, forms and scripts removed, like a readability extractor) and `full` (only scripts/styles removed), plus a word count.
- **`PAYLOAD_ISLAND_PATTERNS` + `derive()`** — records which framework data blobs a page ships (`__NEXT_DATA__`, `__NUXT__`, Apollo, Redux, `self.__next_f`, `application/json`) and bundles the JSON-LD, text and island names as `page["derived"]`.
- **`normalise()`** — canonical URL form (lowercase host, no trailing slash, no fragment).
- **`Page`, `Bundle` dataclasses** — the bundle's shape: per-page status, role, headers, HTML, redirect chain, derived data; plus site, coverage, robots report, sitemap URLs, notes and probes.
- **`_discover_sitemap_urls()`** — walks sitemap indexes up to 3 levels (at most 8 XML fetches), checking robots.txt before each one, and returns page URLs only.
- **`build()`** — the crawl itself: fetch robots.txt → discover sitemap → probe `/llms.txt` → apply crawl-delay (shrinking the page budget if the delay is long) → build a deterministic frontier (homepage, then sitemap order, then homepage links sorted) → fetch pages within the deadline, skipping anything robots.txt disallows → set `run_status` (`complete` / `partial` / `blocked` / `failed`) → return the `Bundle` with coverage numbers and the per-agent robots report.
- **`__main__`** — `python3 bundle.py <url> [out.json]` builds a bundle on its own.

### `scripts/robots.py` (254 lines) — robots.txt parser + AI crawler list
- **`RETRIEVAL_AGENTS`** — crawlers that fetch pages to answer users (`OAI-SearchBot`, `ChatGPT-User`, `Claude-SearchBot`, `Claude-User`, `PerplexityBot`, `Perplexity-User`, `Applebot`, `Googlebot`, `Bingbot`). Blocking these stops citations.
- **`TRAINING_AGENTS`** — crawlers that gather training data (`GPTBot`, `ClaudeBot`, `CCBot`, `Google-Extended`, `Applebot-Extended`, `Bytespider`). Blocking these doesn't affect citations.
- **`AMBIGUOUS_AGENTS`** — `meta-externalagent`.
- **`classify_agent()`** — returns `retrieval` / `training` / `ambiguous` / `unknown` for a token.
- **`Rule`, `_compile()`** — one Allow/Disallow line compiled to a regex (`*` wildcard, `$` end anchor); `specificity` is its length for longest-match precedence.
- **`Group`** — a `User-agent` block: its agent names, rules and crawl-delay.
- **`Robots` class**:
  - `_parse()` — reads the file into groups and sitemap lines.
  - `_match_groups()` — groups that apply to an agent (exact, case-insensitive name match; `*` only if no specific group matches).
  - `_deciding_rule()` — longest matching rule wins; ties go to Allow.
  - `explain()` — the deciding rule for an agent + path, and whether it came from the `*` group.
  - `allowed()` — yes/no for an agent + path; a 4xx robots.txt allows everything, a 5xx or unreachable one blocks everything.
  - `crawl_delay()` — the delay for an agent.
  - `agent_report()` — for every known AI crawler: class, which sampled paths are blocked, fully/partially blocked, blocked via wildcard or by name, and the deciding rules. This goes into the bundle.
  - `unrecognised_agent_tokens()` — finds `User-agent` names that are a truncated prefix of a known crawler (e.g. `Claude`), which match nothing. Feeds A8.

### `scripts/model.py` (194 lines) — finding + severity table
- **Docstring** — the severity rules in brief.
- **`ORDER`, `COVERAGE_FLOOR`, `_idx`, `_clamp`** — severity ordering and helpers.
- **`SEVERITY_TABLE`** — every check ID → base severity, gate (`access` / `extractability` / `interpretability` / `freshness` / `engagement`) and Round-2 mechanism letter. One row per check the skills can emit (a test enforces this).
- **`HURTS_BOTH`, `hurts_for()`** — the plain-language tag: engagement checks → `user_retention`, everything else → `ai_discoverability`, and B6/E4/E9 → `both`.
- **`BLAST`** — site-wide 1.0, template 0.8, single page 0.5.
- **`Finding` dataclass** — the fields a sub-skill supplies (`check_id`, `title`, `evidence`, `suggested_action`, `affected_urls`, `blast_radius`, `confidence`, `measurement_basis`, `status`, `blocked_by`, `intent_signals`, `detail`) plus those computed later (`id`, `severity`, `severity_rationale`, `gate`, `mechanism`, `hurts`).
  - `finalise()` — looks up the base severity, demotes single-page findings by one band (only with ≥3 pages crawled), applies the caps (heuristic measurement → at most medium, heuristic confidence → at most high, latent or confirm-intent → at most low), writes the step-by-step `severity_rationale`, and assigns `F-001`-style IDs.
  - `to_report()` — the report form of a finding: required fields first, then extras; `affected_urls` capped at 25.

### `references/report-schema.md` (52 lines)
Explains every report field in plain words: the required ones, why `total_findings`
includes latent findings, why each extra field exists (including `hurts`), and the
design rules (one finding per check type rather than per URL, reproducible evidence,
every action has a `verify`).

### `references/severity-rationale.md` (70 lines)
The severity arithmetic written out, a table giving every check's base severity with a
one-line reason, and why blocked findings are marked latent instead of hidden.

### `references/jsonld-normalisation.md` (47 lines)
The contract for `page["derived"]["jsonld"]`: why parsing happens once in the crawl
layer, how each input shape is handled (`@graph`, arrays, nested entities, IRI `@type`,
comment-wrapped scripts), the narrow definition of "malformed" (only when `json.loads`
fails), and the derived fields (`types_present`, `sameas`, `dates`, `text`).

## `skills/crawl-access-audit/` — Gate 1: can AI crawlers get in?

### `SKILL.md` (61 lines)
When to use ("can AI assistants reach my site?"), input (a bundle), a 6-step procedure
covering A7 → A1 → A3/A2 → A5/A4/A6 → A8 → confirm-intent classification, the output
format, and references.

### `scripts/check_access.py` (362 lines)
Reads a bundle and prints a JSON array of findings.
- **`SNIPPET_SUPPRESSORS`** — `nosnippet`, `noarchive`, `max-snippet:0`.
- **`load_bundle()`, `ok_pages()`** — read the bundle; keep 2xx pages with HTML.
- **`_robots_directives()`** — combines the `X-Robots-Tag` header with meta robots/googlebot tags.
- **`EXCLUDABLE_ROLES`, `CONTENT_ROLES`, `MAX_DELIBERATE_NOINDEX_SHARE`** — the inputs to the deliberate-vs-defect decision.
- **`_classify_noindex()`** — noindex on ≤34% of pages and only on legal/utility/search templates → `confirm_intent` with reasons.
- **`_classify_ai_block()`** — retrieval agents blocked by name (not via `*`), with other AI agents also named and a path-scoped rather than whole-site block → `confirm_intent` with reasons.
- **`run()`** — emits, in order:
  - **A7_site_unreadable** — no readable page at all (returns immediately).
  - **A1_retrieval_agent_blocked** — robots.txt blocks retrieval agents; lists blocked training agents as not a defect, quotes the deciding rules, includes an example robots.txt fix, and passes `blocked_paths` so the orchestrator can mark findings latent.
  - **A3_noindex / A3_noindex_utility** — pages carrying noindex.
  - **A2_snippet_suppressed** — pages that forbid snippets.
  - **A5_canonical_problem** — off-domain canonical, or no canonical on product/pricing/blog pages.
  - **A4_redirect_chain** — more than two redirect hops.
  - **A8_robots_token_unrecognised** — truncated user-agent names that bind nothing.
  - **A6_sitemap_missing** — no sitemap was found or read.

  Each finding carries `evidence`, `affected_urls`, `blast_radius`, `confidence` and a `suggested_action` with `how` steps and a `verify` command.

### `references/bot-taxonomy.md` (65 lines)
Tables of retrieval vs training crawlers (operator and role), the ambiguous Meta agent,
how the classes are used (only retrieval blocks raise a finding), and the RFC 9309
parsing rules, including the A8 exact-match rule.

### `references/deliberate-vs-defect.md` (53 lines)
The exact conditions under which noindex (`A3_noindex_utility`) or an AI crawler block
(A1) is reported as `confirm_intent`, why the posture changes rather than the finding
disappearing, and the test cases showing the classifier still separates deliberate from
broken.

## `skills/fact-extractability-audit/` — Gates 2–3: can a machine read and trust the fact?

### `SKILL.md` (64 lines)
When to use (reachable, but facts are missing or wrong in AI answers), input, a 7-step
procedure (tiering B1 → shells B4 → structured data C1 → contradiction C2 → entity
C3/C6 → quotability C5/X1/X2 → filler B6), output and references.

### `scripts/check_extractability.py` (618 lines)
Reads a bundle and prints a JSON array of findings.
- **`PAYLOAD_ISLANDS`** — regexes that pull the contents of framework data blobs out of the raw HTML.
- **`FACT_PATTERNS`** — regexes for a price, a phone number and an email.
- **`ROLE_OBLIGATIONS`** — `pricing`/`product` must show a price; `contact` must show a phone number or email.
- **`ANAPHORA`** — paragraph openers such as "This", "It", "Our platform" that lose meaning when quoted alone.
- **`payload_text()`** — concatenates all payload-island contents on a page.
- **`nodes_of_type()`** — JSON-LD nodes of given types.
- **Price helpers** (`_PRICE_TOKEN`, `_as_number`, `_price_tokens`, `_types_of_offer`) — find currency-marked prices in text as numbers, and detect `AggregateOffer`.
- **Brand-name helpers** (`_brand_tokens`, `_name_surfaces`, `LEGAL_SUFFIX`) — compare `Organization.name` and `og:site_name` with case, punctuation and "Inc/Ltd/LLC" removed.
- **`tier_of()`** — where a fact lives: T0 prose, T1 JSON-LD, T2 meta or payload, T3 nowhere.
- **Filler helpers** (`SENTENCE`, `FILLER_*` constants, `_sentences`, `site_common_sentences`) — sentences that appear on ≥60% of pages (needs ≥4 pages).
- **`run()`** — loops over pages collecting evidence, then emits:
  - **B1_fact_absent** (T3) — one finding per missing fact type, with a `curl | grep` command to reproduce.
  - **B1_fact_script_only** (T2) — the fact is only in a script payload or meta tag.
  - **B4_empty_shell** — under 30 words plus a `#root`/`#app`/`#__next`/`#__nuxt` mount.
  - **C1_structured_data_invalid** — JSON-LD that fails to parse.
  - **C1_structured_data_absent** — no JSON-LD on important page types.
  - **C2_markup_text_contradiction** — the JSON-LD price appears nowhere among the page's visible prices.
  - **C5_faq_content_unmarked** — ≥3 question headings without FAQPage markup.
  - **C6_entity_name_conflict** — two brand names sharing no words.
  - **B6_filler_heavy** — >45% of a 300+ word page is site-wide repeated sentences.
  - **C3_entity_unanchored** — homepage lacks `Organization` with `sameAs`.
  - **X1_low_quotability** — many 25–90 word paragraphs open with an unresolved reference.
  - **X2_no_citation_anchor** — ≥3 h2/h3 headings, none with an `id`.

### `references/extraction-tiers.md` (70 lines)
Why raw-HTML text extraction is the measurement (retrieval crawlers don't run
JavaScript), the T0–T3 table, the payload islands parsed, where expected facts come from
(URL role table — not the site's own markup, which would be circular), and the declared
limits (XHR-loaded facts, no layout information, extractor approximation, C2 caution).

## `skills/freshness-corroboration-audit/` — is the fact current and trusted?

### `SKILL.md` (54 lines)
When to use (cited but outdated or wrong), input (the clock comes from the bundle, so
replays are stable), a 6-step procedure (dates → D1/D3 → D2 → D4 → D5 → record D6 as
skipped), output and references.

### `scripts/check_freshness.py` (234 lines)
Reads a bundle and prints `{findings, checks_skipped}`.
- **`STALE_MONTHS`** (18), **`COPYRIGHT`**, **`ISO_DATE`**, **`PRESS_PATH`** — the thresholds and patterns.
- **`_clock_from()`** — "now" is the bundle's `audited_at`, not the wall clock.
- **`_months_since()`** — the age of a date in months.
- **`run()`** — per page: copyright years from `full` text; date signals from `<time>`, date meta tags, `Last-Modified` and JSON-LD dates; prices on pricing/product pages; press/news links. Then emits:
  - **D2_stale_copyright** — latest copyright year is older than last year.
  - **D1_no_date_signals** — a blog/news/article page has no date at all.
  - **D3_content_stale** — the newest date on such a page is >18 months old.
  - **D4_internal_contradiction** — pricing/product pages show different price sets.
  - **D5_no_corroboration_hooks** — no page links to a press/newsroom/news section.
  - Always adds **D6_cross_web_corroboration** to `checks_skipped` (needs a search backend).

### `references/freshness-signals.md` (37 lines)
The date signals actually read, the D1/D2/D3 thresholds with the reasoning behind each,
how D4 compares price sets, and what corroboration is checked on the site (D5, C3) versus
not checked (D6).

## `skills/engagement-audit/` — do visitors who arrive stay and act?

### `SKILL.md` (61 lines)
When to use (traffic arrives but doesn't act), input, a 9-step procedure (E5, E1, E2,
E3, E4, E6/E7, E9, E10, record skipped checks), output and references. States that
findings are risk factors capped at medium, not measured behaviour.

### `scripts/check_engagement.py` (328 lines)
Reads a bundle and prints `{findings, checks_skipped}`.
- **`VAGUE_LINKS`** — "click here", "read more", "learn more", …
- **`STOPWORDS`** — words ignored when comparing a title with its body.
- **`accessible_name()`** — a control's name from `aria-label`, `title`, input `value`, image `alt` or its text.
- **`_zoom_suppressed()`** — parses the viewport meta tag; flags `user-scalable=no/0` or `maximum-scale < 2`.
- **`run()`** — always starts `checks_skipped` with colour contrast and Core Web Vitals (they need a browser or field data). Per page it gathers evidence, then emits through the `add()` helper (every finding is `heuristic` / `static_heuristic`):
  - **E1_form_friction** — >5 required fields or unlabelled inputs.
  - **E2_vague_link_text** — ≥3 or ≥15% vague links.
  - **E3_unnamed_controls** — ≥3 buttons/links with no accessible name.
  - **E4_images_missing_alt** — ≥3 or ≥30% images with no `alt`; the fix also covers facts locked inside images.
  - **E10_no_next_step** — 200+ word non-legal page whose main content has no internal link, form, `tel:` or `mailto:`.
  - **E5_no_lang** — `<html>` has no `lang`.
  - **E6_heading_structure** — no `h1`.
  - **E7_zoom_disabled** — pinch-zoom blocked.
  - **E9_promise_payoff_mismatch** — no distinctive title/description word appears in the body.

### `references/engagement-checks.md` (33 lines)
The evidence bar (a number and a selector), a table of every shipped check with its
threshold and reasoning, and a table of what is deliberately not checked (consent
banners, Core Web Vitals, contrast, above-the-fold, action verbs, image CTAs, bounce
rate) and why.

## `tests/` — offline test suite

### `tests/run_tests.py` (347 lines)
Runs with no network: `python3 tests/run_tests.py` → currently **88 checks**.
- **`check()`** — prints ok/FAIL and tallies results.
- **RFC 9309 robots.txt conformance** — `*` group, longest match, Allow ties, 4xx/5xx behaviour, empty Disallow, sitemap capture.
- **Agent taxonomy** — retrieval vs training classification, case-insensitive.
- **Severity table** — blast demotion, caps, rationale text, coverage floor, `hurts` tags.
- **Extraction tiering** — runs `check_extractability.py` on `extraction_tiers` and checks T0/T2/T3 pages are told apart.
- **JSON-LD normalisation** — `@graph`, list `@type`, nested offers, IRI/prefixed types, comment-wrapped blocks, malformed vs empty, multiple blocks.
- **Text normalisation** — navigation and scripts excluded from `extracted`; footer kept in `full`.
- **Exact token matching** — `User-agent: Claude` binds nothing and is reported; real tokens are not; the Google-CloudVertexBot/Meta-ExternalFetcher false-positive guard.
- **Intent-aware severity** — confirm-intent caps and precedence.
- **Price comparison** — years and bare numbers aren't prices.
- **Severity-table integrity** — every check ID a script can emit has a table row, and vice versa.
- **Regression fixtures** — replays the fixture bundles end to end through `audit.py`.

## Development tools outside the marketplace (not in the zip)

### `tools/validate_submission.py`
Submission check: `python3 tools/validate_submission.py brand-ai-readiness-audit-v2.1`.
Checks the manifest (exactly one entrypoint, paths exist, no unlisted folders),
agentskills.io frontmatter limits, report conformance on a replay (required fields,
summary counts match the findings, JSON-schema validation), two replays are
byte-identical, README names every skill, no model weights, junk files or absolute
